# CampusCore v1.0.0

CampusCore 1.0.0 is the first stable source and self-hosted deployment release of the open-source student-management system. It provides an ASP.NET Core 9 API backed by PostgreSQL, a React/TypeScript Web/PWA frontend, and a minimal Chromium browser companion.

## Product capabilities

- Student records, guardians, academic years, sections, classes, enrollment, faculty and role-based access.
- Attendance, leave, marks, grading, report cards, timetable, announcements, and attachments.
- Bulk student operations, search, exports, dashboards, auditable sensitive changes, and institution configuration.
- Web/PWA offline shell, accessible navigation, theme preferences, printable views, and operational empty/error states.
- Health and readiness endpoints, production configuration validation, migration automation, and guarded backup/restore scripts.

## Downloadable release assets

The GitHub Release workflow builds these packages from the same checked commit. Download the matching archive for the intended platform, and check its SHA-256 against `SHA256SUMS.txt`.

- `campuscore-api-v1.0.0-win-x64.zip`: **self-contained Windows x64 server** containing `CampusCore.Api.exe`.
- `campuscore-api-v1.0.0-linux-x64.tar.gz`: **self-contained Linux x64 server** containing `CampusCore.Api`.
- `campuscore-api-v1.0.0-osx-arm64.tar.gz`: **self-contained Apple Silicon macOS server** containing `CampusCore.Api`.
- `campuscore-api-v1.0.0.tar.gz`: framework-dependent API deployment package (requires matching .NET runtime).
- `campuscore-web-v1.0.0.tar.gz`: static Web/PWA production assets.
- `campuscore-companion-v1.0.0.zip`: browser companion, for manual developer loading, not a published store listing.
- `campuscore-android-v1.0.0-debug-TEST-ONLY.apk`: **debug/testing only**, not Play Store-ready; it is built against a non-production example API origin and will not connect to a real institution deployment without rebuilding with its correct HTTPS API URL.
- `migrations.sql`: idempotent EF Core migration SQL for operator review.
- `VERSION` and `SHA256SUMS.txt`: release version and artifact integrity data.

**Important:** The Windows/macOS/Linux executables are **server applications**, not stand-alone desktop student-management clients. They require a provisioned PostgreSQL database and correctly secured configuration. There is no embedded database or hosted production backend included in the archives.

## First deployment

For a container-based evaluation from the exact Git tag:

```bash
git clone --branch v1.0.0 --depth 1 https://github.com/sanskarIN/campuscore.git
cd campuscore
cp .env.example .env
# Replace development-only credentials with private, randomly generated values.
docker compose up -d --build --wait
```

For operational production deployment use [docs/deployment.md](../deployment.md), [docs/setup.md](../setup.md), [docs/release.md](../release.md), and [docs/backup-restore.md](../backup-restore.md). Production installations must configure HTTPS reverse proxy, secure JWT credentials, allowed hosts, trusted CORS origins, database backups, and administrative bootstrap policy before onboarding real records.

## Verification and limitations

Releases are published only after the tagged-source workflow builds and validates the API, Web/PWA, extension and Android debug assembly, generates migration SQL and checksums, and verifies required main-branch CI, CodeQL, E2E, Android, deployment, performance, and version-consistency workflows.

- Android APK signing and a production API URL remain deployment-owner responsibilities. **Do not publish the debug APK to the Play Store.**
- Browser companion store submission and icons/review are separate from this release.
- The PWA shell can work offline but live student data APIs require server connectivity.
- API server packages do not contain a database, credentials or a configured external URL.
- No production uptime/security guarantee is implied by passing automated checks.
